# KoreaMate V3 实施计划

依据：`docs/superpowers/specs/2026-09-14-koreamate-v3-design.md`

## 执行原则

- 现有 `frontend`、`backend` 和未提交修改只读保留，V3 在新目录建设。
- 每个阶段均交付可运行增量，不等待全部 Provider 接入后才集成。
- 先写契约和验收测试，再补实现。
- Mock 只能用于测试和本地演示，界面必须明确标识，不得冒充实时数据。
- 外部 Provider 未取得 API Key 时实现 Adapter、配置检查与契约测试，不虚构联调成功。

## 阶段 0：安全基线

目标：确保旧版本和用户工作区修改可恢复。

任务：

1. 记录当前分支、HEAD、未提交文件与差异统计。
2. 不暂存、不覆盖、不删除现有用户修改。
3. 所有 V3 提交仅包含 `apps`、`packages`、新增基础设施和 V3 文档。

验收：`git status --short` 中原有修改保持不变。

## 阶段 1：Monorepo 骨架与共享契约

目标：一次安装、一条命令启动 Web 与 API。

任务：

1. 将根项目配置为 npm workspaces。
2. 创建 `apps/web` Next.js App Router 应用。
3. 创建 `apps/api` NestJS 应用。
4. 创建 `packages/contracts`，使用 Zod 定义 API、SSE 和错误契约。
5. 添加根级 `dev`、`build`、`test`、`lint` 和 `typecheck` 命令。
6. 增加 `.env.example` 与配置校验，不写入真实密钥。

测试：

- Contracts Schema 正反例单元测试。
- API `/api/v1/health` 集成测试。
- Web 首页渲染测试。

验收：根目录安装、构建、类型检查与测试通过；Web/API 可同时启动。

## 阶段 2：极简首页与双模式会话

目标：两个入口可创建会话并发送消息。

任务：

1. 实现极简首页，只显示旅行规划、AI 翻译和最多一条最近任务。
2. 建立 `Conversation`、`Message` 与 `Job` Prisma 模型。
3. 实现创建会话和发送消息接口。
4. 实现幂等键检查。
5. 实现 SSE 任务事件及断线恢复所需事件 ID。
6. 建立统一对话界面与自然语言进度反馈。

测试：

- 同一幂等键不会创建重复消息或任务。
- TRAVEL 与 TRANSLATION 会话不能混用错误输入。
- SSE 事件顺序、结束事件和重连游标正确。
- E2E 从两个首页入口分别进入正确会话。

## 阶段 3：文字翻译闭环

目标：完成第一个真实 AI 能力。

任务：

1. 定义 `TranslationProvider` 与标准结果。
2. 实现一个可配置的真实模型/翻译 Provider。
3. 实现语言识别、礼貌程度和旅行场景提示。
4. 在同一页面展示大号韩文、中文含义、播放入口和折叠详情。
5. 保存用户明确要求保留的翻译历史。

测试：Provider 契约、非法输出、超时、未配置状态和中韩互译 E2E。

## 阶段 4：旅行需求与基础行程

目标：一句话生成可保存、可修改的基础行程。

任务：

1. 建立 Trip、TripRequirement、TripVersion、ItineraryDay 与 ItineraryItem。
2. 实现需求增量提取与合并。
3. 实现一次只追问一个关键问题的规则。
4. 实现基础 Planner 与结构化输出校验。
5. 实现确定性日期、预算和跨日校验。
6. 实现局部修改、新版本与恢复。

测试：需求合并、问题选择、版本不可变、预算求和及局部修改 E2E。

## 阶段 5：旅游、地图、天气和汇率

目标：用真实外部数据增强路线。

任务：

1. 实现 Provider Registry 和通用调用记录。
2. 接入 Korea Tourism MCP。
3. 接入地图/地理编码 Provider。
4. 接入天气 MCP。
5. 接入汇率 MCP。
6. 建立 Place、PlaceSource 与 TripResource 快照。
7. 实现地点归一化、去重、新鲜度和来源引用。
8. 使用坐标、营业信息和天气验证行程。

测试：统一 Provider 契约、真实 smoke test、超时和降级 E2E。

外部前置：申请 TourAPI、地图、天气和汇率所需开发者凭证。

## 阶段 6：航班与酒店

目标：查询真实候选并推荐一个默认方案。

任务：

1. 验证 RollingGo 航班/酒店 MCP 的认证、授权、字段和稳定性。
2. 分别实现 FlightProvider 与 HotelProvider Adapter。
3. 标准化日期、机场、住客、房型、价格、币种和深链接。
4. 保存带过期时间的查询快照。
5. 默认展示一个推荐，按需展开少量备选。
6. 不实现站内交易。

测试：价格新鲜度、空结果、无效日期、Provider 降级和推荐排序。

外部前置：获得可用于公开 Web 项目的 API Key 与使用许可。

## 阶段 7：图片、语音与朗读

目标：在单一翻译入口完成多模态交互。

任务：

1. 实现预签名上传与附件表。
2. 接入 OCR Provider 和菜单结构化翻译。
3. 接入语音识别与韩文朗读。
4. 增加媒体保留期限和清理任务。
5. 保留文字输入作为所有失败场景的回退方式。

测试：文件类型/大小、过期清理、OCR 空结果、语音超时和端到端菜单翻译。

## 阶段 8：知识、引用、收藏与 Memory

目标：提高推荐质量，同时保持用户可控。

任务：

1. 建立 KnowledgeDocument、Embedding 版本与来源状态。
2. 使用 PostgreSQL/pgvector 实现检索。
3. 在 Planner 输入中区分事实、动态数据和经验内容。
4. 实现 SavedItem 业务服务及自然语言“记住这个地方”。
5. 实现 Memory 提取、置信度、覆盖与删除。
6. 在回复与行程中展示简洁引用。

测试：用户隔离、来源追踪、重复知识、旧 Memory 被替代和删除生效。

## 阶段 9：公开部署与质量门槛

目标：生成可公开访问的 Web 地址。

任务：

1. Web 部署到 Vercel。
2. API 与必要 MCP 容器部署到 Railway 或 Render。
3. PostgreSQL 与对象存储配置到 Supabase。
4. 仅在异步任务需要时启用 Redis。
5. 配置 CORS、限流、请求 ID、结构化日志和密钥脱敏。
6. 建立 Provider 健康检查和轻量内部诊断页。
7. 执行构建、Lint、类型、单元、集成、契约和 E2E 全量检查。

验收：公开地址完成旅行规划和翻译主路径；未配置或失败的 Provider 均可信降级。

## 首轮实施切片

本轮只执行阶段 0 和阶段 1，产出：

- 不影响旧代码的 V3 目录骨架
- 可启动的 Next.js Web
- 可启动的 NestJS API
- 首批共享契约与测试
- 根级统一开发和验证命令

完成后以测试结果和文件清单交付，再继续阶段 2。
