# KoreaMate V3 第八阶段 8A：地点收藏设计

## 目标

让用户以一次点击或一句自然语言保存韩国地点，并在独立的“我的收藏”页面中查看、删除或用于新行程。收藏入口必须简单、可撤销，并遵循现有游客使用与登录归并机制。

## 导航

侧边栏固定为三个主入口，顺序如下：

1. 开始出发吧
2. 历史记录
3. 我的收藏

登录入口或当前账户继续固定在侧边栏底部。桌面收起状态显示三个图标；移动端抽屉显示图标和文字。收藏不在侧边栏直接展开列表。

“我的收藏”路由为 `/saved`。首页仍只保留旅行规划和翻译两个核心入口，不增加收藏卡片。

## 收藏对象

第一版只收藏已经由 KoreaMate 核验并保存到 `Place` 表的地点，不收藏自由文本、酒店报价、航班或整份行程。

每条收藏包含：

- 地点 ID。
- 用户 ID 或游客 ID，两者只存在一个。
- 可选短备注。
- 收藏时间和更新时间。

地点名称、韩文名称、地址、坐标、地图链接和来源继续读取规范化 `Place` 与最新 `PlaceSource`，不在收藏记录中复制，避免地点更新后收藏仍显示旧数据。

现有 `Place.name` 保留供应商规范名称，并新增可空的 `nameZh`。新规划绑定地点时，使用 Planner 生成并经当前行程确认的中文地点名填充 `nameZh`；已有地点从最近的行程项目标题做一次尽力回填。收藏页显示 `nameZh ?? name`，当 `name` 与中文显示名不同时再显示 `name` 作为韩文原名。系统不为了生成中文名额外调用翻译接口。

## 收藏方式

### 行程卡片

已经绑定 `Place` 的行程项目显示心形收藏按钮：

- 未收藏：轮廓心形，名称为“收藏地点”。
- 已收藏：实心状态，名称为“取消收藏”。
- 点击后立即更新状态。
- 请求失败时恢复原状态并显示简短错误。

按钮点击区域至少 44 × 44 像素，不能只依赖颜色表达状态。

### 自然语言

旅行对话识别以下意图：

- “记住景福宫”
- “收藏这个地方”
- “把刚才那个咖啡店存起来”

处理原则：

- 文本明确包含地点，且能唯一匹配当前会话已有的核验地点时直接收藏。
- “这个地方”“刚才那个”等指代只在当前会话最近一个明确地点可唯一确定时执行。
- 有多个候选时只追问一次，让用户选择地点。
- 没有核验地点时先搜索并展示候选，不能凭名称创建未经核验的收藏。
- 收藏成功后返回一句确认，不重新生成行程。

自然语言查看“我收藏的地方”时，回复收藏摘要并提供进入 `/saved` 的操作，不在对话中输出长列表。

## 我的收藏页面

页面使用单列极简卡片。每条仅显示：

- 中文显示名；若有不同的韩文名，在下一行显示韩文。
- 城市或地址。
- 可选备注。
- 地图入口。
- “用它规划行程”。
- 删除操作。

默认按最近收藏排序。第一版不加入搜索、标签、文件夹、批量编辑或复杂筛选。

空状态显示“还没有收藏地点”，并提供“去规划旅行”按钮。

### 用它规划行程

点击后进入 `/travel`，创建新的旅行对话，并预填：

```text
请把「地点中文名」加入我的韩国行程
```

系统不自动发送，用户仍可补充日期、预算或同行人数后再提交。

### 删除与撤销

点击删除后：

1. 收藏项立即从列表移除。
2. 页面底部显示短暂的“已移除 · 撤销”。
3. 撤销期限为 5 秒；点击后恢复同一收藏。
4. 超过期限后不再显示撤销，但用户仍可重新收藏地点。

删除只删除 `SavedPlace`，不会删除规范化地点、来源或既有行程。

## 数据模型

新增 `SavedPlace`：

```text
id
placeId
userId nullable
guestId nullable
note nullable
createdAt
updatedAt
```

约束：

- `userId` 与 `guestId` 必须且只能存在一个。
- 登录用户按 `(userId, placeId)` 唯一。
- 游客按 `(guestId, placeId)` 唯一。
- 删除用户、游客或地点时级联删除收藏。
- `note` 最长 240 字符。

登录归并时，将当前游客收藏合并到用户：

- 用户尚未收藏的地点直接迁移。
- 重复地点保留用户现有记录。
- 用户记录没有备注而游客记录有备注时，采用游客备注。
- 归并完成后删除游客收藏。

## API

新增：

```text
GET    /api/v1/saved-places
POST   /api/v1/saved-places
PATCH  /api/v1/saved-places/:id
DELETE /api/v1/saved-places/:id
```

`POST` 输入 `placeId` 与可选 `note`。重复收藏采用幂等语义，返回现有记录而不是报错。

所有接口使用现有账户或游客 Cookie。服务端绝不接受客户端提供 `userId` 或 `guestId`。读取、修改和删除均按当前身份隔离。

行程计划结果补充稳定的 `place.id`，前端通过地点 ID 查询和切换收藏状态，不使用地点名称去重。

## 自然语言意图

收藏意图在旅行任务入口优先识别，早于重新规划：

```text
用户消息
  → 收藏/取消收藏/查看收藏意图？
      → 是：解析当前会话地点并执行收藏服务
      → 否：继续现有旅行问答或规划
```

新增任务事件：

- `travel.saved-place.ready`
- `travel.saved-place.question`

前端收到成功事件后更新对应行程项目的收藏状态并显示简短确认；不会生成新版本行程。

## 错误与边界

- 地点不存在：提示“暂时找不到这个地点，请先搜索或生成行程”。
- 指代不明确：展示最多三个当前会话候选供选择。
- 请求重复：幂等返回已收藏状态。
- 网络失败：恢复按钮原状态，保留页面内容。
- 未登录游客：正常使用，由游客 Cookie 隔离。
- 地图来源链接缺失：隐藏地图入口，不生成虚假链接。

## 测试

后端覆盖：

- 用户和游客收藏、列表、备注和删除。
- 不同身份之间不可读取或删除对方收藏。
- 同一地点重复收藏幂等。
- 登录归并、重复去重和备注合并。
- 删除收藏不影响地点和行程。
- 自然语言明确地点、唯一指代、多候选和无核验地点。

前端覆盖：

- 侧边栏第三个入口在展开、收起和移动端均可访问。
- 行程地点收藏状态、乐观更新和失败回滚。
- 收藏页加载、空状态、地图入口和预填规划。
- 删除后 5 秒撤销。
- 键盘操作、44 像素点击区域和可访问性名称。

验收标准：用户能从行程项目一次点击收藏地点，也能在旅行对话中说“记住这个地方”；收藏在独立侧边栏页面可见，游客登录后不丢失，且可一次点击带入新的旅行规划。

## 不在本切片范围

- 收藏酒店报价、航班和整份行程。
- 标签、文件夹、搜索和批量管理。
- 向量知识检索。
- 长期偏好 Memory。
- 推荐内容的完整来源引用。
